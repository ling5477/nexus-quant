# Shadow 观察窗口精度

正式创建计划和 artifact 中的窗口使用 `Instant`，保留原冻结输入的纳秒精度。原命令重放必须匹配完整窗口，相差 1 纳秒仍是不同输入；查询结果不能通过修改当前准入窗口来推测。

PostgreSQL `timestamptz` 的微秒精度不足以独立保存该输入。V20 为 `shadow_runs` 的开始和结束分别增加 `smallint` 纳秒余数（0—999）。JDBC 在绑定前向下取到微秒，再保存余数；三个正式读取方按同一规则还原。不能先让驱动四舍五入，再叠加余数，也不能将幂等比较降为微秒比较。跨秒、纪元之前和不足一微秒的窗口遵守同一规则。

历史行的余数默认 0，保留现有字段和值，不重建历史未保存的信息。空窗口保持空；空时刻只能有 0 余数。顺序约束比较完整的时间戳和余数，继续允许领域既有的相等和空窗口；新 release-bound 创建计划仍要求结束严格晚于开始。

V1—V19 不变。迁移为事务内增量 DDL，设置锁和语句超时，验证约束后完成，不批量改写旧窗口。新应用必须在 V20 成功后启动。旧应用可继续读取已有列、写微秒或空窗口，但不能正确消费新纳秒窗口；不得将旧应用与新应用混合写入或把回退旧 JAR 当作精度兼容方案。应用/制品恢复以保留数据库和经验证的 forward fix 为准，不删除新增列或改写 Flyway 历史。

该变更仅修正同一个 Shadow 事实的持久化与只读投影，不改变发布准入、权限、交易状态或启动能力。真实私有数据、LIVE、真实交易和发布授权继续独立。
